# 会话操作

命令入口是环境说明“仓库根”下 `网页会话池/会话池.py`；显式传 `--db` 指向使用者自己的数据库。先核对当前程序 `--help`，不能把会话标题当作 ID 或登记事实。

## 登记与领取

初次登记从已核对环境文件取得“仓库根”，读取其下的 `文档/部署.md`。本技能复制到宿主技能目录后也按该仓库根定位，不向技能目录上级拼接文档路径。日常不重建数据库，不要求用户人工逐图登记。

1. 生成唯一 `job_id`，用 `profile-list --state enabled` 读取启用档案。
2. 实际读取档案哨兵会话，按准确 thread_id 和 marker 调用 `profile-detect --job-id … --probe-json …`。只接受唯一匹配 observation_id。用户明确当前账号时可用 `profile-select-manual --job-id … --profile-id … --reason …`；不是模型猜账号的通道。
3. `lease --job-id … --observation-id …` 原子领取未用会话。没有 ready 槽位就报告缺口，不复用已用会话充当新角色。
4. 实际读取所领 thread_id，保存发送前最后答复标识及当前轮次；`record --thread-id … --job-id … --event-type baseline_recorded --details-json …` 记录来源。
5. 按环境文件中“仓库根”下 `文档/网页协作.md` 的交接格式发送一次完整角色任务。接口接受才记录 `dispatch_accepted`，之后实际读到本次用户轮次，再绑定等待。发送结果不确定先读原会话，不重发、不释放占用。

上文省略号表示从真实工具返回或环境中取值，不是可原样运行的命令。跨系统完整命令示例见手动指南。

## 语义接口与等待

当前适配使用宿主的 `list_threads`、`read_thread`、`send_message_to_thread`。实际名称、参数及是否支持普通 ChatGPT 会话以当次工具定义为准；不能拿仅支持本地 Codex 任务的接口冒充普通网页会话工具。

不再加载自制等待脚本。通过宿主真实自动化工具建立或复用已授权的定时检查；能力缺失或返回结构不兼容时报告，不猜测兼容。

从已核对环境文件取得“仓库根”，读取其下的 `文档/等待与恢复.md`，按其中单轮检查、限流退避、暂停验收和返工更新规则执行。

同任务一个检查安排；同角色续发后核对新的真实派发轮次和基线，再更新并恢复检查。有新实质答复且空闲后暂停检查并完整回收，不以截断预览验收。

## 结果与回收

候选必须属于发送基线之后的本次派发轮次。实际观察后记录 `result_observed`；验证失败、超时、取消分别使用已有 `validation_failed`、`timed_out`、`cancel_requested`，不创造事件名。

同角色返工、澄清继续用原任务和租约。闭环后：

```text
complete --thread-id 实际会话编号 --job-id 实际任务编号 --outcome 实际结果 --return-state used
```

成功发过业务任务的会话回收为 used；副作用不明使用 failed 或 retired。只有确认从未发送且记为 cancelled_before_dispatch 才可回到 ready。`list` 和 `events` 用于核对，不把数据库状态当网页完成证明。

原生要求新角色或独立上下文时另领会话；不声明新会话等于无记忆或升级模型。明确安全拒绝不允许通过迁移会话恢复被拒动作。
