# Codex 协助部署

部署目标是使用者自己的环境，不能直接复制维护者的账号与路径。先阅读 [README](../README.md) 与 [兼容性](兼容性.md)。全局规则为可撤销的文字约定，不绕过任何平台限制。

## 1. 核对来源与能力

确认下载来源、标签或提交；读取脚本，不加载来源不明的网页文字为代码。检查 Python 版本至少3.10。Node.js 是维护者测试依赖，日常等待运行在 Codex 工具中。

从宿主真实工具定义确认能够列出、读取和发送普通 ChatGPT 会话，并具有异步工具让出与收取结果机制。当前参考为 list_threads/read_thread/send_message_to_thread；名称相同但只支持本地任务也不满足条件。缺少任一必要能力，报告不能启用自动网页委托，不更换为浏览器点击方案。

文件任务还需要实际 Google Drive 读写能力和登录授权。核对上传接口的输入：若只接受 file_uri，确认网页自身实际暴露的文件生成工具能产出所需引用，不能把字符串路径或聊天正文当引用。允许网页用自身已授权的云端临时文件工具，这与操作用户本机不同。缺少上传源能力则报告不能完成网页文件直传，不切换模式或伪造文件。不要要求用户把密码或 API 密钥写入本仓库。

## 2. 选择目录与保留现有配置

核对仓库根、宿主实际使用的全局配置位置、本地运行目录及业务项目。合并目标必须是经确认由当前宿主加载的 Markdown 指令文件，不是任意结构化应用配置文件；无法确认类型、位置或作用域时不执行合并。记录确认依据，不要假设所有平台的用户目录相同。建议将运行数据库与本地配置放在不公开的位置；本仓库下 `本地配置/`、`运行/`、`备份/` 已忽略，但使用者也可选择其他目录。

读取现有全局文件和同名技能。记录修改前字节摘要、备份路径、目标文件与本次拥有的内容。备份保存在本机，不提交公共仓库。

## 3. 实例化和合并

复制 [项目环境模板](../配置/项目环境示例.md) 到选定本地位置，填写已核对值；尚未连接的项目或云盘写“未配置”。有必要字段缺失，不启用相应依赖动作。

将 [全局节点模板](../配置/全局节点.md) 作为一个完整块合并；仅将唯一字段 `网页协作环境文件：未配置` 的值替换为实际环境文件绝对路径。保留该字段在所有权标记内，不另行在块末或其他位置追加同名字段。

全局块只保存分工和入口，操作细则位于仓库的[网页协作](网页协作.md)。检查环境文件中的仓库根确实能定位该文件及其引用；不要把仓库移走后留下失效入口，也不把专项正文重新复制进全局。升级 v0.1.0 时保留已实例化的环境路径和原有账号、数据库、Drive 设置，只比较合并本方案拥有的块与文件。

- 原文件不存在：确认位置和授权后创建。
- 没有本方案标记：保留原文并追加一块。
- 有且仅有一对完整标记：比较内容，只更新此块。
- 标记重复、不完整或已有不同版本：报告冲突并核对，不能贪婪匹配覆盖大段内容。

路径和参数按当前 shell 正确引用。合并前展示准确差异；已有部署授权内执行，不再重复询问常规可逆文件写入。不能覆盖用户自己的其他规则，也不能把文档模板的“最高优先级”解释为高于系统指令。

网页执行参考可直接保留在仓库，不强制安装技能。用户选择安装时，先确认实际技能目录与中文名称支持，逐文件比较同名内容，记录备份和本次拥有文件；不能自动部署旧技能或第三方修改脚本。

## 4. 建立自己的会话池

检测可运行的 Python 命令，Windows 可为 `py -3`，其他环境可为 `python3`。从仓库根先执行：

```text
Python命令 网页会话池/会话池.py --db 自己的准确数据库路径 init
```

这里是参数说明，完整的跨系统可替换示例见 [手动部署](手动部署.md)。始终传入 --db，避免在未知目录生成另一套数据库。

让用户选择账号和用于当前账号识别的已授权会话，实际读取一个明确标记，调用 `profile-register`；用户指定可用的新会话后通过语义接口读其真实 ID，调用 `register-batch`。不根据截图标题或随意编写 ID 登记。标记不应包含秘密。

日常领取与续接按 [会话操作](../skills/网页执行/参考/会话操作.md)。首次可只登记一个角色槽位。多个账号是保留能力，不要求使用者拥有多个账号。原生模型要求不能满足时报告，由使用者决定是否放宽。

## 5. 文件交付与首次任务

按实际 Google Drive 能力核对用户指定目录及准确 ID，配置自动同步或明确的显式取回方式。不要假设特定系统必有桌面同步客户端；缺少自动同步仍可说明手动交付，不能冒充自动同步成功。

完整交接 [首次协作示例](../示例/首次协作/任务.md)。依次核对租约、发送前基线、发送接受及实际派发轮次，按 [等待与恢复](等待与恢复.md) 调用等待。收到候选后完整读回，并检查实际 Drive 文件与本地内容。无文件能力时可做纯文字诊断，但不得声称文件闭环通过。

## 6. 完成与记录

回报实际版本、全局文件、环境文件、备份、运行数据库位置、工具检查、示例结果和交付方式。原始账号与会话记录只留使用者本地，公共反馈先去除个人数据。

更新和卸载规则见等待与恢复。再次部署相同版本应无重复块；配置完成不等于未来会话必然具备工具。
